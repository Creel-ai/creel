## Codebase Patterns
- Python source lives in src/taskrunner/ (package name is taskrunner, not creel yet)
- FastAPI daemon API is in src/taskrunner/daemon/api.py — use APIRouter for new endpoint groups
- Task models and loading in src/taskrunner/models.py — use load_all_tasks()
- Scheduler is APScheduler-based in src/taskrunner/scheduler.py
- NEW: Full cron system in src/taskrunner/cron/ (manager, store, models, executor, delivery, tool)
- Cron store already persists run history — check src/taskrunner/cron/store.py before building new history storage
- Config is agent.yaml (YAML), loaded as Pydantic models
- Telegram channel support added in src/taskrunner/channels/telegram.py
- Daemon service layer in src/taskrunner/daemon/service.py wraps business logic
- CREEL_HOME defaults to ~/.creel/ — state dir for daemon.sock, daemon.pid, daemon.log
- Tasks dir configurable, defaults to tasks/ relative to working directory
- Existing tests in tests/ — run with pytest
- pyproject.toml uses hatchling build system
- Bridge (FastAPI host bridge) is in src/bridge/ — separate from daemon
- Dashboard static dir path: `_DASHBOARD_STATIC_DIR` computed from `Path(__file__).resolve().parent.parent / "dashboard_static"` in api.py
- SPA fallback uses catch-all `/{full_path:path}` route — must be registered AFTER all other routes
- `_mount_dashboard()` is a no-op when dashboard_static/ dir is missing (graceful degradation)
- Tests run with `.venv/bin/python -m pytest tests/ -x -q`
- Dashboard scaffold: Vite 7 + React 19 + TypeScript 5.9 (strict mode enabled by default in template)
- Build script: scripts/build-dashboard.sh — npm ci + npm run build + copy dist/ to dashboard_static/
- Vite dev proxy: /api/* and /v1/* proxied to localhost:8099
- MUI v6 + Emotion installed; ThemeProvider in dashboard/src/ThemeContext.tsx wraps the app
- Dark mode toggle persists to localStorage key `creel-theme`; use `useThemeMode()` hook for mode/toggle
- Theme factory in dashboard/src/theme.ts — `buildTheme(mode)` creates MUI theme
- React Router v6 in dashboard/src/App.tsx — routes defined as children of Layout route
- BrowserRouter wraps the app in main.tsx
- Layout component in dashboard/src/Layout.tsx — AppBar (fixed) + responsive Drawer + Outlet
- Sidebar nav groups: Control, Workspace, System — defined as `NAV_GROUPS` array in Layout.tsx
- Page components in dashboard/src/pages/ — one file per page (OverviewPage.tsx, etc.)
- Drawer width: 240px; mobile breakpoint: `theme.breakpoints.down('md')`
- Dashboard API router in src/taskrunner/daemon/api_dashboard.py — prefix="/api", mounted via `app.include_router(dashboard_router)` in api.py
- Access DaemonService in endpoint handlers via `request.app.state.service`
- Agent definition accessible via `service._agent_def` (AgentDefinition model)
- TypeScript `erasableSyntaxOnly` disallows `public` param properties — use explicit field declarations
- MUI Grid v2 uses `size` prop: `<Grid size={{ xs: 12, md: 4 }}>` (not `xs={12} md={4}`)
- API client: dashboard/src/api/client.ts — typed fetch wrapper, add new API methods here
- Types for API responses defined in client.ts alongside fetch methods
- Task CRUD API router in src/taskrunner/daemon/api_tasks.py — prefix="/api/tasks", mounted via `app.include_router(tasks_router)` in api.py
- Task CRUD supports both form-field requests and raw_yaml passthrough for create/update
- Soft-delete pattern: move files to .deleted/ subdir instead of permanent removal
- Task toggle pattern: read raw_yaml via GET /api/tasks/{name}, regex-replace `enabled:` line, PUT back with raw_yaml field
- Types for API responses defined in dashboard/src/api/client.ts: TaskSummary, TaskDetail, TaskUpdateRequest
- CodeMirror 6 packages: codemirror (basic setup), @codemirror/state, @codemirror/view, @codemirror/lang-yaml, @codemirror/theme-one-dark
- js-yaml for YAML↔JSON conversion in browser; @types/js-yaml for TypeScript
- CodeMirror editor must be recreated when dark mode changes — theme is set at EditorState creation time
- Form↔YAML sync pattern: only convert on tab switch (not per-keystroke) to avoid feedback loops
- TaskEditPage serves both /tasks/new (create) and /tasks/:name (edit) — `useParams().name` determines mode
